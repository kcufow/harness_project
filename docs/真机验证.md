# 真机验证 · dsh 安装与配置清单

`npm run check`（build + 单测 + 端到端冒烟）全部使用构造数据，未覆盖真实 Harness 的审批弹窗与会话日志。本文记录把两个插件装进真实 `dsh` 所需的环境、配置与验证步骤。

## 一、版本门槛

数据来自 npm registry 的 `@deepseek-ai/dsh` 包元数据（2026-11-10 查询）：

| 项 | 值 |
| --- | --- |
| `latest` | `0.2.2-rc.1` |
| `engines.node` | `>=24.9.0` |
| `bin` | `dsh` → `lib/bin.js` |
| 关键依赖 | `@deepseek-ai/cordis ~4.1.0`、`@deepseek-ai/schemastery ~3.19.0` |

**版本必须对齐**：本仓库 `package.json` 锁的是 cordis 4.1.0 / schemastery 3.19.0，正好对应 0.2.2 线。`0.2.1-rc.5` 依赖 cordis `~4.0.5` / schemastery `~3.18.5`——不要为了迁就旧 Node 降版本，插件 API 会错配。社区教程里流传的「Node `^20.19` 或 `>=22`」是旧版口径，对当前 latest 不成立。

## 三、必配三项

1. **DeepSeek API Key**。Web UI 的 Settings → Models 填写，或写入配置文件。读取优先级：进程环境 → `~/.dsh/.credentials.yaml`（托管存储，0600）→ 工作目录 `.env` → `~/.dsh/.env`。
   ```bash
   # 兜底层
   echo "DEEPSEEK_API_KEY=sk-xxx" >> ~/.dsh/.env
   # 或仅当前终端
   export DEEPSEEK_API_KEY=sk-xxx
   ```
   变量名是 `DEEPSEEK_API_KEY`，不是小程序项目用的 `DEEPSEEK_KEY`。不要把密钥提交进仓库。
2. **工作区**。Web UI 里 Select workspace 添加目录后**必须点选**；只添加不选中，输入框仍是灰的、无法发消息。建议先用一个空测试目录，不要直接指向本仓库。
3. **profile 初始化**。首次 `npx @deepseek-ai/dsh web` 才会生成 `~/.dsh/profiles/web/`（插件依赖 + `cordis.patch.yml`）。装插件前必须先跑一次。

## 四、路径与端口

| 路径 | 用途 |
| --- | --- |
| `~/.dsh/` | 主目录，可用 `DSH_HOME` 改 |
| `~/.dsh/profiles/web/` | web profile：插件挂载、依赖、`pnpm-workspace.yaml` |
| `~/.dsh/sessions/` | 会话日志（zstd 压缩，两级目录） |
| `~/.dsh/.env`、`~/.dsh/.credentials.yaml`、`~/.dsh/settings.yaml` | 兜底凭据、托管凭据、全局运行时设置 |
| `http://127.0.0.1:3080` | 默认 Web UI；端口占用时用 `dsh web --port 8080` |

辅助命令：`dsh web --dump-config` 打印插件组合树，用来确认插件是否真的挂载。

## 五、完整步骤

```bash
# 1. 在用户自己的终端（Node 25.8.1）首次启动，初始化 web profile
npx @deepseek-ai/dsh web
# 浏览器打开终端打印的地址，填 API Key、选工作区，然后 Ctrl+C 停掉

# 2. 打包两个插件（在本仓库根目录）
npm ci && npm run build && npm pack --workspaces

# 3. 装进 web profile
npx @deepseek-ai/dsh plugin --profile web add ./packages/dangerous-op-precheck/dangerous-op-precheck-0.1.0.tgz
npx @deepseek-ai/dsh plugin --profile web add ./packages/skill-usage-audit/skill-usage-audit-0.1.0.tgz

# 4. 重启 dsh web 后验证
npx @deepseek-ai/dsh plugin --profile web why dangerous-op-precheck
npx @deepseek-ai/dsh web --dump-config
npx @deepseek-ai/dsh web
```

配置示例见各包的 `cordis.example.yml`；把它作为 profile 的 patch 层注入后可覆盖 `rules` / `knownSkills` 等默认值。

## 六、验证清单

- [ ] 预检插件：配一条 `rm` 的 `ask` 规则，触发一次 `bash rm -rf <临时目录>`，确认审批弹窗里出现编号检查清单，且拒绝后工具未执行。
- [ ] 预检插件：配一条 `.env` 的 `block` 规则，确认直接返回拒绝理由。
- [ ] 审计插件：装一个技能包并调用 2–3 个技能，再让模型调用 `skill_usage_report`，确认报告里的调用次数、成功/失败数与真实操作一致。
- [ ] 审计插件：确认报告头部数据源为 `sessionQuery`；若走 jsonl 兜底，核对 `~/.dsh/sessions/` 里的真实文件名能被识别。
- [ ] `dsh web --dump-config` 能看到两个插件在组合树里。

## 七、常见坑

- **npx 零安装没有全局 `dsh` 命令**：所有 `dsh ...` 要写成 `npx @deepseek-ai/dsh ...`；桌面版可通过菜单 Manage dsh Command → Install 注册全局命令。
- **装完必须重启** `dsh web`，插件树在启动时才加载。
- **profile 归属**：`web` 与 `headless` 各自独立，装进哪个只影响哪个；桌面版 profile 被 Electron 独占，命令行 `--profile desktop` 会被拒绝，只能用 GUI。
- **命令行装插件走 profile 内置 pnpm**，系统不必装 pnpm；git 源插件若报 `allowBuilds`，按提示把 key 加进 profile 的 `pnpm-workspace.yaml`。
- **国内下载慢**：`npm config set registry https://registry.npmmirror.com`。
- **本地 tgz 路径**：相对路径锚定执行命令的目录；若 `add <tgz>` 不被接受，改用本地目录 `add ./packages/<包名>`（需已 build）。
- Web UI 默认只监听 loopback，不要 `--host 0.0.0.0`；远程访问用 SSH 端口转发。启动链接里的 token 不要外发。
