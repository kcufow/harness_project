## 三、必配四项

1. **Node ≥24.9.0**。会话内若要代跑，需 `export PATH=/opt/homebrew/bin:$PATH`。
2. **`pnpm` 在 PATH 上**。`dsh plugin` 会直接 spawn 系统 `pnpm`，找不到就报 `ENOENT` 并回滚安装。可用 corepack 免全局安装：
   ```bash
   corepack pnpm --version          # 首次会自动下载
   # 或做一个临时 shim 放进 PATH：
   # #!/bin/sh
   # exec corepack pnpm "$@"
   ```
3. **DeepSeek API Key**。Web UI 的 Settings → Models 填写，或写入配置文件。读取优先级：进程环境 → `~/.dsh/.credentials.yaml`（托管存储，0600）→ 工作目录 `.env` → `~/.dsh/.env`。
   ```bash
   echo "DEEPSEEK_API_KEY=sk-xxx" >> ~/.dsh/.env   # 兜底层
   export DEEPSEEK_API_KEY=sk-xxx                  # 或仅当前终端
   ```
   变量名是 `DEEPSEEK_API_KEY`，不是小程序项目用的 `DEEPSEEK_KEY`。不要把密钥提交进仓库。
4. **工作区 + profile**。Web UI 里 Select workspace 添加目录后**必须点选**；首次启动会生成 `~/.dsh/profiles/web/`。发起对话前至少要有模型凭据和一个被选中的工作区。

## 四、路径与端口

| 路径 | 用途 |
| --- | --- |
| `~/.dsh/` | 主目录，可用 `DSH_HOME` 改 |
| `~/.dsh/profiles/web/` | web profile：`package.json`、`cordis.yml`、`cordis.patch.yml`、`pnpm-workspace.yaml` |
| `~/.dsh/sessions/` | 会话日志（zstd 压缩，两级目录） |
| `~/.dsh/.env`、`~/.dsh/.credentials.yaml`、`~/.dsh/settings.yaml` | 兜底凭据、托管凭据、全局运行时设置 |
| `http://127.0.0.1:3080` | 默认 Web UI；端口占用时用 `--port 8080` |

辅助命令：`dsh web --dump-config` 打印组合树（不启动服务），`dsh --dump-config-schema` 打印 patch 的 schema，`dsh plugin --help` 查看插件命令。

## 五、完整步骤

```bash
# 0. 前提
export PATH=/opt/homebrew/bin:$PATH          # Node 25.8.1
corepack pnpm --version                     # 让 pnpm 可用

# 1. 首次启动，初始化 web profile（或直接跑一次 --dump-config）
npx @deepseek-ai/dsh web
# 浏览器打开终端打印的地址，填 API Key、选工作区，然后 Ctrl+C 停掉

# 2. 在本仓库根目录打包 —— tgz 产物落在【仓库根目录】
npm ci && npm run build && npm pack --workspaces
# → ./dangerous-op-precheck-0.1.0.tgz、./skill-usage-audit-0.1.0.tgz

# 3. 装进 web profile（用绝对路径最稳，相对路径会锚定到 profile 目录）
npx @deepseek-ai/dsh plugin --profile web add "$PWD/dangerous-op-precheck-0.1.0.tgz"
npx @deepseek-ai/dsh plugin --profile web add "$PWD/skill-usage-audit-0.1.0.tgz"

# 4. 挂载：把两个包的 cordis.example.yml 内容合入
#    ~/.dsh/profiles/web/cordis.patch.yml，或启动时用 --patch 传入
npx @deepseek-ai/dsh web \
  --patch "$PWD/packages/dangerous-op-precheck/cordis.example.yml" \
  --patch "$PWD/packages/skill-usage-audit/cordis.example.yml" \
  --dump-config                      # 先只打印组合树确认挂载

# 5. 正式启动（去掉 --dump-config），重启后插件才生效
npx @deepseek-ai/dsh web --patch ... --no-open
```

`dsh plugin add` 只把包装成 profile 依赖，**不会自动加载**：插件没声明 `dsh.bundle`，dsh 会给出 `installed as a plain dependency, not a profile layer` 警告，必须靠上面的 patch 层插入条目。

## 七、常见坑

- **npx 零安装没有全局 `dsh` 命令**：所有 `dsh ...` 要写成 `npx @deepseek-ai/dsh ...`；桌面版可通过菜单 Manage dsh Command → Install 注册全局命令。
- **缺 `pnpm` 会直接失败**：报 `spawn pnpm ENOENT`，且安装被完整回滚（`package.json`、`pnpm-lock.yaml`、`node_modules` 都还原）。
- **peer 版本不匹配会被拒绝**：报 `Plugin <name> is incompatible with dsh <ver>: requirements {...}`，同样回滚。不要用 `allow-version --accept-risk` 绕过——运行时 API 可能真的不兼容，应修插件依赖。
- **`cordis.example.yml` 必须是顶层数组**：`- insert:` 作为数组元素，插件行缩进在其下。写成顶层 `insert:` 对象会被 dsh 报 `must be a top-level YAML array of loader patch entries`。
- **`npm pack --workspaces` 的产物在仓库根目录**，不是各包目录下；用绝对路径传给 `plugin add`。
- **装完必须重启** `dsh web`，插件树在启动时才加载；`--dump-config` 只验证配置，不会 require 插件代码。
- **profile 归属**：`web` 与 `headless` 各自独立；桌面版 profile 被 Electron 独占，命令行 `--profile desktop` 会被拒绝，只能用 GUI。
- **国内下载慢**：`npm config set registry https://registry.npmmirror.com`。
- Web UI 默认只监听 loopback，不要 `--host 0.0.0.0`；远程访问用 SSH 端口转发，启动链接里的 token 不要外发。
