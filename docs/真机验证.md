## 三、必配四项

1. **Node ≥24.9.0**。会话内若要代跑，需 `export PATH=/opt/homebrew/bin:$PATH`。
2. **`pnpm` 在 PATH 上**。`dsh plugin` 会直接 spawn 系统 `pnpm`，找不到就报 `ENOENT` 并回滚安装。可用 corepack 免全局安装：
   ```bash
   corepack pnpm --version          # 首次会自动下载
   # 或做一个临时 shim 放进 PATH：
   # #!/bin/sh
   # exec corepack pnpm "$@"
   ```
3. **DeepSeek API Key**。Web UI 的 Settings → Models 填写，或写入配置文件。读取优先级：进程环境 → `~/.dsh/.credentials.yaml`（托管存储，0600）→ 工作目录 `.env` → `~/.dsh/.env`。
   ```bash
   echo "DEEPSEEK_API_KEY=sk-xxx" >> ~/.dsh/.env   # 兜底层
   export DEEPSEEK_API_KEY=sk-xxx                  # 或仅当前终端
   ```
   变量名是 `DEEPSEEK_API_KEY`，不是小程序项目用的 `DEEPSEEK_KEY`。不要把密钥提交进仓库。若写在 `~/.zshrc`，只有交互式 shell 能读到，会话内代跑要用 `/bin/zsh -ic '...'` 让进程继承。
4. **工作区 + profile**。Web UI 里 Select workspace 添加目录后**必须点选**；首次启动会生成 `~/.dsh/profiles/web/`。发起对话前至少要有模型凭据和一个被选中的工作区。

## 五、完整步骤

```bash
# 0. 前提
export PATH=/opt/homebrew/bin:$PATH          # Node 25.8.1
corepack pnpm --version                     # 让 pnpm 可用

# 1. 首次启动，初始化 web profile（或直接跑一次 --dump-config）
npx @deepseek-ai/dsh web
# 浏览器打开终端打印的地址，填 API Key、选工作区，然后 Ctrl+C 停掉

# 2. 在本仓库根目录打包 —— tgz 产物落在【仓库根目录】
npm ci && npm run build && npm pack --workspaces
# → ./dangerous-op-precheck-0.1.0.tgz、./skill-usage-audit-0.1.0.tgz

# 3. 装进 web profile（用绝对路径最稳，相对路径会锚定到 profile 目录）
npx @deepseek-ai/dsh plugin --profile web add "$PWD/dangerous-op-precheck-0.1.0.tgz"
npx @deepseek-ai/dsh plugin --profile web add "$PWD/skill-usage-audit-0.1.0.tgz"

# 4. 两个包已声明 dsh.bundle，装完自动挂载，无需手写 patch
npx @deepseek-ai/dsh web --dump-config   # 不带 --patch，组合树里就有两个插件

# 5. 自定义配置（可选）：在 profile 的 cordis.patch.yml 里按同一 id 重写整行 config
#    patch 是整行替换、用户层优先级更高；完整示例见各包 cordis.example.yml

# 6. 正式启动（去掉 --dump-config）
npx @deepseek-ai/dsh web --no-open --port 13080

# 7. 验证安装产物可加载、接线正确
npm run smoke:installed
```

两个包的 `package.json` 都声明了 `dsh.bundle`，指向包内 `cordis.patch.yml`。`plugin add` 会读这个字段，把包名写入 `dsh.profile.bundles` 并自动应用 bundle patch——**安装即挂载**。早期未声明时 dsh 会给出 `installed as a plain dependency, not a profile layer` 警告，才需要手写 patch 或 `--patch` 传入；市场的 registry 安装路径更会直接拒绝没有 `dsh.bundle` 的包（`not-a-bundle`）。

覆盖默认配置时注意：patch 对同一 `id` 是**整行 `config` 替换**，不是逐字段合并；profile 用户层在 bundle 层之后应用，最后写入者生效。

## 七、常见坑

- **npx 零安装没有全局 `dsh` 命令**：所有 `dsh ...` 要写成 `npx @deepseek-ai/dsh ...`；桌面版可通过菜单 Manage dsh Command → Install 注册全局命令。
- **缺 `pnpm` 会直接失败**：报 `spawn pnpm ENOENT`，且安装被完整回滚（`package.json`、`pnpm-lock.yaml`、`node_modules` 都还原）。
- **peer 版本不匹配会被拒绝**：报 `Plugin <name> is incompatible with dsh <ver>: requirements {...}`，同样回滚。不要用 `allow-version --accept-risk` 绕过——运行时 API 可能真的不兼容，应修插件依赖。
- **`cordis.example.yml` 必须是顶层数组**：`- insert:` 作为数组元素，插件行缩进在其下。写成顶层 `insert:` 对象会被 dsh 报 `must be a top-level YAML array of loader patch entries`。
- **`npm pack --workspaces` 的产物在仓库根目录**，不是各包目录下；用绝对路径传给 `plugin add`。
- **装完必须重启** `dsh web`，插件树在启动时才加载；`--dump-config` 只验证配置，不会 require 插件代码。
- **别再手写挂载 patch**：有了 `dsh.bundle` 后，profile 的 `cordis.patch.yml` 应只放**覆盖项**（按 id 重写整行 config）；把完整 `- insert:` 条目再写一遍会造成重复。虽按 last-write-wins 不会崩，但容易分不清到底哪层生效。用户已有定制规则时，保留 profile 层的整行 config 即可。
- **profile 的 `node_modules` 里没有 peer 依赖**：`dsh plugin add` 用 pnpm 只装插件本体，`@deepseek-ai/cordis` / `dsh-tools` / `schemastery` 由 dsh 宿主提供。直接 `import()` 安装产物会报 `ERR_MODULE_NOT_FOUND`，这不是插件缺陷；仓库的 `npm run smoke:installed` 用 resolve hook 复现宿主解析（默认仓库根 `node_modules`，可用 `DSH_RUNTIME_NODE_MODULES` 指向 dsh 安装目录）。
- **Web UI 的 token 是一次性换 cookie**：`/?token=...` 返回 303 并下发 HttpOnly cookie；直接 `curl -L` 会因第二次请求不带 cookie 而 401，脚本里要用 cookie jar（`-c` / `-b`）。
- **`/rpc` 是 WebSocket 逻辑 channel，不是 REST 接口**：GET 返回 404、POST 返回 405；想查运行时工具清单要走 WS，不能靠 curl。
- **npx 下载被中断会留下残缺缓存**：表现为 `startup failed: 2 required plugins did not activate`、35 个内置插件 import 失败（缺 `yaml/index.js`、`zod/index.js` 等）。这不是项目插件问题，重装一份干净的 dsh 副本即可（见第十节）。
- **在托管会话内启动 dsh 会撞 fs broker**：WorkBuddy 的 `node-brokered-fs-shim.cjs` 会让 `session-projection-cache` 报 `Broker request outcome unknown: write EPIPE` 并提示 `1 entry did not activate`。服务仍可用，但**建议在用户自己的终端启动**做最终交互验证。
- **profile 归属**：`web` 与 `headless` 各自独立；桌面版 profile 被 Electron 独占，命令行 `--profile desktop` 会被拒绝，只能用 GUI。
- **国内下载慢**：`npm config set registry https://registry.npmmirror.com`。
- Web UI 默认只监听 loopback，不要 `--host 0.0.0.0`；远程访问用 SSH 端口转发，启动链接里的 token 不要外发。

### 运行时加载语义（本轮新发现）

`~/.dsh/profiles/web/node_modules/` 下只有两个插件本体，没有 peer 依赖，因此：

```bash
node -e "import('file:///.../dangerous-op-precheck/lib/index.js')"
# ERR_MODULE_NOT_FOUND: Cannot find package '@deepseek-ai/schemastery'
```

这是 dsh 的加载语义而非插件缺陷：`installAnchor` 指向 dsh 自身安装目录，`createRuntimeResolution` 负责运行时解析，peer 由宿主提供。本仓库新增 `scripts/dsh-module-hook.mjs` + `scripts/dsh-register.mjs` 复现该语义，`scripts/smoke-installed.mjs` 据此直接验证 tarball 发布产物（入口、`Config`、`tools/pre-execute`、`skill_usage_report`、报告生成）。启动日志只报 1 个无关内置 entry 未激活，也印证两个项目插件在 dsh 进程内激活无报错。
